# 渲染系统说明

## 核心问题：CPU 怎么让 GPU 画东西？

CPU 有自己的内存（RAM），GPU 有自己的显存（VRAM）。CPU 不能直接操作 GPU 的数据，需要通过 **OpenGL（图形接口）** 来沟通：

```
CPU 内存 (RAM)  ──→  glBufferData()  ──→  GPU 显存 (VRAM)
                          |
                     glDrawElements()
                          ↓
                     屏幕上画出来
```

整个渲染流程可以分成三步。

---

## 第一步：告诉 GPU「画什么」—— 数据 + 缓冲区

### 一个矩形由什么构成？

GPU 只认识三角形。一个矩形需要拆成 **2 个三角形**：

```
   A ──── B         三角形1:  A → B → C
   │ \    │         三角形2:  C → D → A
   │   \  │
   D ──── C
```

每个**顶点**（A/B/C/D）包含：
- 位置（x, y, z）
- 纹理坐标（u, v）
- 颜色（r, g, b, a）
- 其他附加数据

### VertexBuffer（顶点缓冲区）—— 存"不重复的顶点"

把 4 个不重复顶点打包上传到 GPU：

```
顶点数组:  [A位置, A纹理, A颜色]  [B...]  [C...]  [D...]
                ↑                                ↑
          第0个顶点                          第3个顶点
```

### IndexBuffer（索引缓冲区）—— 存"用哪几个顶点拼三角形"

GPU 不知道哪三个顶点组成一个三角形，你得告诉它索引顺序：

```
索引数组:  [0, 1, 2,   2, 3, 0]
             ↑  三角形1     ↑  三角形2
```

**为什么叫 IndexBuffer？**  
因为它存的不是顶点坐标，而是 **顶点数组里第几个位置的编号（索引）**。和书目录一个道理——目录（索引）告诉你内容在第几页，不是把内容重复抄一遍。

**没有 IndexBuffer 会怎样？**  
你得写成 `[A, B, C, C, D, A]` —— 6 个顶点，A 和 C 重复了两遍。1000 个矩形你的顶点数据要多传 50%，显存浪费。

### VertexArray（顶点数组对象 / VAO）—— 把上面的东西绑在一起

VAO 的职责很简单：**记录「当前的 VertexBuffer 和 IndexBuffer 是谁」**，画的时候不用一个个重新绑定。

通俗理解：
- VertexBuffer = 你写好的材料清单
- IndexBuffer = 清单上的编号（第 1 项、第 2 项……）
- VertexArray = 一个文件夹，把清单和编号夹在一起，画的时候直接拿文件夹用

### 封装成类的目的（RAII）

```
构造函数 → glGenBuffers()  → 向 GPU 申请一块显存
          glBufferData()   → 把数据从 RAM 上传到 VRAM
析构函数 → glDeleteBuffers() → GPU 自动释放这块显存
```

这样你只管 `new VertexBuffer(data)`，忘了 `delete` 也会自动清理，不会内存泄漏。

## 第二步：告诉 GPU「怎么画」—— 着色器（Shader）

GPU 是一根流水线，着色器就是流水线上每个工位的**操作手册**：

```
顶点着色器 (Vertex Shader)
  │  输入：顶点位置(x,y,z)
  │  做：坐标变换（把模型坐标 → 屏幕坐标）
  │  输出：变换后的顶点
  ▼
片段着色器 (Fragment Shader)  
  │  输入：插值后的颜色/纹理坐标
  │  做：算每个像素最终颜色
  │  输出：屏幕上这个像素(R,G,B,A)
  ▼
屏幕像素
```

### Shader.glsl 文件解释

```
#type vertex       ← 下面这段是顶点着色器
layout(location = 0) in vec3 a_Position;   // 接收第0个输入：位置
layout(location = 1) in vec2 a_TexCoord;   // 接收第1个输入：纹理坐标
uniform mat4 u_ViewProjection;              // 来自 CPU 的变换矩阵
void main() {
    gl_Position = u_ViewProjection * vec4(a_Position, 1.0);
}

#type fragment     ← 下面这段是片段着色器
uniform sampler2D u_Textures[16];           // 纹理图片
void main() {
    FragColor = texture(u_Textures[index], v_TexCoord);  // 从纹理里取颜色
}
```

## 第三步：发号施令 —— RenderCommand & Renderer

### RenderCommand（渲染命令）

封装最简单的 GPU 指令，一次一个动作：

| 命令 | 作用 |
|------|------|
| `SetClearColor(r,g,b,a)` | 设置用啥颜色擦黑板 |
| `Clear()` | 清空屏幕（用上面设的颜色填满） |
| `SetBlend(true)` | 开启透明混合 |
| `SetViewport(x,y,w,h)` | 设置画布区域 |

### Renderer（渲染器）+ SpriteBatch（精灵批处理）

画一个精灵（带纹理的矩形）需要做的事情：

```
for 每个精灵:
    1. 计算 4 个顶点的位置（考虑旋转/缩放）
    2. 计算纹理坐标
    3. 把顶点数据塞进内存数组（不立刻传 GPU）

攒够 1000 个精灵 → Flush() 一次：
    4. 一次性上传所有顶点到 GPU
    5. 调用 glDrawElements() 让 GPU 画所有三角形
    6. 画完统一清理
```

**为什么攒一批再画？**  
`glDrawElements()` 调用一次，CPU → GPU 的「聊天」开销是固定的。画 1 个矩形聊一次，和画 1000 个矩形聊一次，时间差不多。所以攒一批能快几百倍。

## OrthographicCamera（正交相机）

相机的本质就是一个**变换矩阵**，决定了：

```
顶点从"这个世界位置是多少" → "屏幕上的像素是多少"
```

正交相机 = 没有近大远小，适合 2D 游戏：

```
投影矩阵把：
  世界坐标 (0 ~ 1280, 0 ~ 720)     ← 游戏逻辑用的
映射到：
  Clip坐标 (-1 ~ 1, -1 ~ 1)        ← GPU 要求的
```

视图矩阵处理「摄像机移动」——摄像机往右移，所有物体看起来往左移。

## 完整渲染一帧的流程

```
1. SetClearColor(0.1, 0.1, 0.15, 1)      // 设背景色（深灰蓝）
2. Clear()                                 // 用这个颜色清屏
  
3. BeginScene(camera)                      // 通知 Renderer：这帧用哪个相机
   │  → Shader.Bind()                     // 激活着色器程序
   │  → 传递 ViewProjection 矩阵          // 告诉着色器坐标怎么变
  
4. DrawQuad(pos, size, tex, color)        // 提交一个精灵
   │  → 计算 4 个顶点位置 + UV
   │  → 写入内存中的顶点数组
   │  → 如果攒满 1000 个 → 自动 Flush
  
5. EndScene()                              // 通知 Renderer：这帧提交结束
   │  → Flush()                            // 如果有剩下的，这一批发出去
   │     → VertexBuffer.SetData()          // 上传数据到 GPU
   │     → Texture.Bind(0..15)             // 绑定纹理到纹理单元
   │     → VertexArray.Bind()              // 绑好 VAO
   │     → glDrawElements()                // GPU 开始画
   │
6. Window.OnUpdate()                       // 交换缓冲区，显示到屏幕
```

## 总结：每个类到底干了什么

| 类 | 一句话 | 类比 |
|----|--------|------|
| `VertexBuffer` | 把不重复的顶点上传到 GPU | 寄一箱原材料到工厂 |
| `IndexBuffer` | 告诉 GPU 用哪几个顶点拼三角形 | 告诉工人「1号+2号+3号拼一组」 |
| `VertexArray` | 把 VBO 和 IBO 绑在一起方便用 | 一个文件夹把图纸和物料清单夹一起 |
| `Shader` | 编译着色器程序，告诉 GPU 怎么处理顶点和像素 | 工厂流水线的操作手册 |
| `Texture` | 把图片上传到 GPU，画的时候贴上去 | 给白模贴上贴纸 |
| `RenderCommand` | 发简单的 GPU 指令 | 单个动作指令（擦黑板、开混合） |
| `OrthographicCamera` | 生成变换矩阵，控制能看到什么 | 摄像机的取景框 |
| `Renderer` | 统一调度上面所有东西，攒批 + 发送 | 工厂的车间主任 |
