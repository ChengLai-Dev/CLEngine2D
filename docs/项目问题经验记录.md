# 项目问题与经验记录

## ScreenToWorld 坐标转换 Bug：屏幕、OpenGL 窗口、世界三个坐标系的混淆

### 背景

在 CanvasView 编辑器中实现鼠标拾取时，需要将鼠标的屏幕位置转换到世界坐标。转换函数 `ScreenToWorld` 的 Y 坐标计算结果一直不正确，经历了多次错误修复。

### 问题现象

点击 CanvasView 中的物体，拾取位置的 Y 方向完全不准确——点 panel 上方，拾取到世界下方；点 panel 下方，拾取到世界上方。X 方向正确。

### 问题定位过程

首先确认了几个事实：

1. 鼠标位置来自 GLFW，是 **屏幕坐标**（原点在窗口左上角，Y 向下）
2. `glViewport` 要求 viewport 像素坐标的原点在 **左下角，Y 向上**
3. 相机投影将 viewport 像素线性映射到世界坐标

原始代码的 Y 转换是：

```
worldY = (screenPos.y - m_rectTop - halfH) / zoom + m_viewCenter.y;
```

从"鼠标到 panel 上边界的距离"出发，但这个距离是 Y 向下的，而相机期望 Y 向上，导致 Y 颠倒。中心点恰好对称所以碰巧正确，掩盖了问题。

尝试修复时又引入了一个错误：

```
viewportBottomY = windowHeight - m_rectTop - m_rectHeight;
worldY = (screenPos.y - viewportBottomY - halfH) / zoom + m_viewCenter.y;
```

`viewportBottomY` 是 OpenGL 窗口坐标（Y 向上）中的值，`screenPos.y` 是屏幕坐标（Y 向下），不同坐标系的值直接相减，数学上无意义，结果全错。

### 根因分析

核心问题是混淆了三个坐标系：

| 坐标系 | 原点 | Y 方向 | 来源 |
|--------|------|--------|------|
| 屏幕坐标 | 窗口左上角 | 向下 | GLFW |
| OpenGL 窗口坐标 | viewport 左下角 | 向上 | glViewport 规范 |
| 世界坐标 | m_viewCenter | 向上 | 相机投影 |

渲染管线的正向流程是：**世界坐标 → NDC → OpenGL 窗口坐标 → 屏幕坐标**。`ScreenToWorld` 要逆向走通这个链，就必须严格对齐每个环节的坐标系约定。

其中最关键、最容易忽略的是：`glViewport` 强制 viewport 像素原点在左下角，这个约定不是引擎代码定义的，而是 OpenGL 规范规定的，代码里看不到。如果不了解这个规范，就无法理解为什么需要先翻转 Y。

### 解决方案

正确的 Y 转换分两步：

1. **Y 翻转**：屏幕 Y → OpenGL 窗口坐标 Y（Y 向上，以 viewport 底部为原点）

    ```
    glviewportY = (m_rectTop + m_rectHeight) - screenPos.y
    ```

    panel 顶部（screen Y 最小）→ `glviewportY` 最大（对应 world top）
    panel 底部（screen Y 最大）→ `glviewportY` 为 0（对应 world bottom）

2. **线性映射到世界坐标**：

    ```
    worldY = (glviewportY - halfH) / zoom + m_viewCenter.y
    ```

    和 X 方向对称：`(local - halfSize) / zoom + center`

X 方向不需要翻转，因为屏幕坐标和 OpenGL 窗口坐标的 X 方向一致（左到右）：

```
glviewportX = screenPos.x - m_rectLeft
worldX = (glviewportX - halfW) / zoom + m_viewCenter.x
```

### 要点总结

1. 渲染管线的正逆向必须使用同一套坐标系约定，不能各算各的
2. `glViewport` 的坐标系约定（左下角原点）来自 OpenGL 规范，了解 API 规范对正确实现拾取至关重要
3. 不同坐标系的值不能直接运算，必须先转换到同一空间
4. 变量命名直接影响代码可读性和维护难度——用 `glviewportX/Y` 明确标注这个中间坐标的来源
